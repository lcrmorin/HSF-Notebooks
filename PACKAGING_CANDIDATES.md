# Packaging candidates

Functions defined inline in a notebook — rather than living in the shared
`quanttoolbox` package — that look clean and generic enough to be worth
promoting into the toolbox later, once a second notebook actually needs
the same thing. Tracked here instead of promoted immediately, so notebook
work isn't gated on a toolbox release for every reusable-looking helper.
Excludes anything that's really just data loading, table/chart formatting,
or plotting tied to one notebook's own dataset or figure — those aren't
toolbox material no matter how many times they're reused within that one
notebook, so they're never listed here in the first place.

Each row also checks whether the function is really filling a gap, or
whether `numpy`/`scipy`/`pandas`/`scikit-learn` — or `quanttoolbox` itself
— already do the job. Several rows below turned out to duplicate a
`quanttoolbox` function under a different name (the same situation as the
project's own hand-rolled `bisection`), not just a numpy/scipy one; those
were fixed in the notebook and removed here rather than just noted.
Promoting a thin reimplementation of something the standard scientific
Python stack (or the project's own toolbox) already ships isn't worth it;
calling the existing function directly is. "None" means no real
equivalent exists; "Partial"/"Close" means a library covers part of it or
covers it under a different convention; "Yes" means an existing library
call could likely replace the function outright.
